# Publishing Management System

Planning and tracking tool for book production, built on the publisher's
_Masterproduktionsplan for bogudgivelser_ ([Research/](Research/)). Each book gets a live
production plan generated from the master plan; the focus is on handling delays and
postponements.

- Plan and roadmap: [docs/PLAN.md](docs/PLAN.md)
- Proposed default durations and dependencies (for client review): [docs/masterplan-defaults.md](docs/masterplan-defaults.md)

## Status

Stage A prototype: frontend only, data stored in the browser.

- Phase 0 (foundations), Phase 1 (scheduling engine), Phase 2 (publications, table view, time
  machine), Phase 3 (interactive Gantt), Phase 4 (delays and replanning) and Phase 5 (progress
  tracking and portfolio) are done.
- Phase 6 (master plan editor, print/PDF, polish) is built; the client test sessions are next
  ([docs/klienttest.md](docs/klienttest.md)).

## Getting started

Requires Node 24+ and pnpm 11.

```bash
pnpm install
pnpm dev          # http://localhost:5173
```

## Using the app

The UI is in Danish.

- **Oversigt** is the Monday overview: counts of what is late, at risk and due, a portfolio Gantt
  with one line per book, and lists of what needs attention and what is due this week.
- **Mine opgaver** shows open work for everyone, one person or one role, across all books. People
  are linked to a book's roles under Planlægning → Roller og personer.
- **Udgivelser** lists all books with release date, forecast, progress, health and next
  milestone. **Ny udgivelse** creates a book from the master plan and a desired release date.
- A book's page shows its plan as a table grouped by phase and track, with the columns from the
  PDF. Status and notes are edited inline. Clicking a current deadline opens a preview of what
  moves and what happens to the release, with four ways to handle the delay. Clicking an
  activity opens a side panel with dates, buffer, dependencies and history. Undo/redo works with
  the buttons or ⌘Z / ⇧⌘Z.
- The **Gantt** tab shows the same plan as a chart. Drag a bar to move it, drag its right edge to
  change the duration, or drag from the dot at its end to another activity to add a dependency.
  While dragging, dashed ghosts show everything that would move. Nothing changes until you
  confirm in the dialog that opens on release. The keyboard works too (Tab, ← →, Enter, Esc).
- **Planlægning** (top right on a book) holds the whole-plan changes, each with a preview of
  what moves before anything is applied: move the release date, pause (HOLD) and resume, make
  the plan binding, save a new baseline, and **Afprøv i et scenarie**. Scenario mode works on a
  copy of the plan: change anything, compare with the real plan (the Gantt shows the real plan
  as dotted outlines), then apply the changes or discard them. Scenarios are kept in memory only.
- The **Finansiering** tab shows secured funding against the minimum, the applications and their
  decisions. The milestone _Finansiering tilstrækkelig_ (which makes the plan binding) can only
  be completed when the minimum is secured or the publisher accepts the risk. Completing the
  _GO / HOLD / NO-GO_ milestone asks for the decision; HOLD pauses the book.
- The **Historik** tab shows how the milestones' forecasts have moved over time (the slip chart),
  the saved baselines, and the change log with filters.
- **Udskriv** (top right on a book) opens a print view: the Gantt chart and the table in the
  PDF's columns, A3 landscape (A4 selectable). Choose "Gem som PDF" in the print dialog for a PDF.
- **Masterplan** shows the template, with a version picker once there is more than one version.
  **Redigér masterplanen** opens a draft of the next version: change durations and deadlines
  inline (dependent activities move along), click an activity to edit everything else
  (responsibility, dependencies, optional, fixed duration, notes), add or remove activities,
  tracks and milestones. The problem list shows what does not hold together; publishing is
  possible when there are no errors. Existing books keep the version they were created from; new
  books use the latest. The "Faktisk" column shows how long finished tasks actually took.

### Two datasets

Switch between them at the bottom of the sidebar.

| Dataset          | What it is                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Demo**         | Five sample books at different stages, generated by simulation. Has the **Tidsmaskine** (time machine) for moving the date. |
| **Rigtige data** | Your own books. Always uses today's real date; nothing is simulated.                                                        |

The datasets are stored separately, so nothing done in the demo affects the real data.

### Tidsmaskine (demo only)

The bar at the top of the page sets the demo's date. Moving forward plays every demo book on:
work starts and finishes, some of it late, and overruns are rescheduled automatically. Moving
back rebuilds the demo data as of that date, so your own demo changes are lost (you are asked
first). The reset button rebuilds the demo as of today. Time stands still while a scenario is
open.

**Fra scenarie…** on the Udgivelser page adds a demo book that follows a named story from the
scenario library (for example "Forfatteren er 3 uger forsinket" or "Fondssvar udebliver → HOLD i
6 uger"). The book is played up to the demo's date and keeps following the story as you move
forward in time. "Alt skrider" with several books is a stress test for the overview. Demo data
from before Phase 5 lacks funding and roles; reset the demo to get them.

### Where data is stored

Everything is stored locally in the browser (IndexedDB, one database per dataset: `pms-demo` and
`pms-real`), including each dataset's own master plan versions. It is not shared between browsers or machines. Use **Eksportér** / **Importér** on
the Udgivelser page to move a dataset as a JSON file; importing replaces the current dataset.
Clearing the site data in the browser deletes everything.

## Structure

```
apps/web          React 19 + Vite frontend (TanStack Router, Tailwind v4, shadcn/ui, Zustand)
packages/domain   Framework-free TypeScript: domain model, master plan template, working-day
                  calendar, scheduling engine, commands with undo/redo, simulation
docs/             Plan and client-facing notes
```

`packages/domain` has no browser dependencies, so the same code can run on a server in Stage B.
See [CLAUDE.md](CLAUDE.md) for a more detailed map of both packages.

## Conventions

- Code and identifiers in English; UI text in Danish via `apps/web/src/i18n/da.ts`.
- Dates are `YYYY-MM-DD` strings. Durations and template offsets are **working days**; offsets
  are relative to the release date (release = 0).
- The domain package never reads the system clock: anything that depends on "today" takes an
  explicit date. In the app, `apps/web/src/lib/clock.ts` is the only place that reads it.
- All plan changes go through domain commands, which log a change event and can be undone.
- The original deadline (_Oprindelig deadline_) is never overwritten.
- The master plan data file is hand-formatted (one line per activity) and excluded from Prettier.
- After adding or renaming a route file, run `pnpm dev` or `pnpm build` once to regenerate
  `routeTree.gen.ts` before typechecking.
